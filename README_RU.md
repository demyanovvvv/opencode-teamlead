# OpenCode TeamLead

**Адаптивная организация задач в OpenCode: ограниченные исполнители, проверенные изменения и независимые настройки проектов.**

[English README](README.md) · [Релизы](https://github.com/demyanovvvv/opencode-teamlead/releases) · [История изменений](CHANGELOG.md)

TeamLead помогает превратить задачу разработки в проверенное изменение. Он выбирает стратегию выполнения, назначает исполнителям ограниченную область работы, запускает детерминированные проверки и интегрирует проверенные патчи. Цель — получить корректный результат быстрее и с минимальными практическими затратами на модели.

## Возможности

- **Адаптивное выполнение:** Direct, Managed или Team в зависимости от задачи.
- **Выбор моделей:** назначения по ролям и пулы с учётом доступности провайдеров, контекста, инструментов, стоимости и предыдущих результатов.
- **Ограниченные исполнители:** явные области чтения и записи, изолированные Git worktree и проверки перед интеграцией.
- **Локальные настройки и история:** бюджеты и данные проектов независимы даже при глобальной установке.
- **Интеграция с OpenCode:** slash-команды, индикатор рядом с полем ввода и раздел TeamLead в Ctrl+P при поддержке TUI-плагинов.
- **Английский и русский языки:** локализация установщика и интерфейса TeamLead.
- **Удаление по области:** отдельные деинсталлеры сохраняют сторонние файлы OpenCode и самостоятельные локальные установки.

## Режимы выполнения

| Режим | Как работает |
| --- | --- |
| Direct | Один исполнитель, проверки затронутых частей и ревью по уровню риска. |
| Managed | Структурированное выполнение с целевыми проверками и условным ревью. |
| Team | Планировщик Lead строит граф задач; независимые исполнители работают параллельно, затем выполняются проверки и ревью. |

TeamLead выбирает минимально полезную глубину организации работы. Дополнительные исполнители используются, когда это улучшает получение проверенного результата.

## Установка

Требования описаны в [документе о совместимости](docs/COMPATIBILITY.md). Скачайте и распакуйте [архив релиза](https://github.com/demyanovvvv/opencode-teamlead/releases) либо используйте локальную копию репозитория. Запускайте установщик из корня дистрибутива.

### Windows

```powershell
.\install.ps1
```

### Linux / macOS

```bash
bash ./install.sh
```

В меню выберите язык и область: **локально в проект** или **глобально для текущего пользователя**. При локальной установке укажите путь к проекту.

Для автоматизированной установки:

```powershell
.\install.ps1 -InstallScope Local -Project C:\projects\my-app
.\install.ps1 -InstallScope Global -Language ru
```

```bash
bash ./install.sh --scope local --project /path/to/my-app
bash ./install.sh --scope global --language ru
```

После установки перезапустите OpenCode. Глобальная установка предоставляет общий код, агентов и команды, а настройки и история остаются в каждом проекте. Подробная инструкция: [INSTALL_RU.md](INSTALL_RU.md).

## Первый запуск

Откройте OpenCode в проекте и выполните:

```text
/lead-doctor
/lead-models
/lead-settings
/lead-plan Исправь ошибку авторизации и добавь регрессионный тест
```

Проверьте план и запустите выполнение:

```text
/lead Исправь ошибку авторизации и добавь регрессионный тест
```

Для задач с изменением файлов нужен Git-репозиторий. Перед выполнением задач с моделями настройте провайдера в OpenCode.

## Команды

| Команда | Назначение |
| --- | --- |
| `/lead` | Выполнить задачу разработки. |
| `/lead-plan` | Посмотреть стратегию выполнения и задачи. |
| `/lead-status` | Открыть статус и историю выполнения. |
| `/lead-resume` | Продолжить подходящий незавершённый запуск. |
| `/lead-models` | Посмотреть подключённые модели и назначения ролей. |
| `/lead-settings` | Настроить стратегию, модели, параллелизм, бюджеты и ревью. |
| `/lead-doctor` | Проверить возможности OpenCode и установленные файлы. |

В дополнительном меню Ctrl+P доступны действия для тех же сценариев.

## Настройки и данные

- `.opencode/teamlead.json` — настройки проекта.
- `.opencode/.teamlead/` — история, статистика, блокировки, патчи и временные рабочие деревья.
- `.teamlead-projects/` в глобальном каталоге конфигурации — проекты, зарегистрированные глобальным плагином.

Настройки включают стратегию выполнения, модели и пулы ролей, параллелизм провайдеров, ограничения допуска по токенам и стоимости, глубину ревью. Подробнее: [бюджетирование](docs/BUDGETING.md) и [состояние и восстановление](docs/STATE_AND_RECOVERY.md).

## Удаление

Закройте OpenCode и запустите деинсталлер из корня дистрибутива:

```powershell
.\uninstall.ps1
```

```bash
bash ./uninstall.sh
```

Выберите локальную или глобальную область. Локальное удаление очищает код, настройки, историю, регистрацию в TUI и рабочие деревья TeamLead. Глобальное также очищает данные зарегистрированных проектов, сохраняя самостоятельные локальные установки и их данные. Сторонние плагины, команды и комментарии JSONC сохраняются.

Глобальная очистка охватывает только зарегистрированные проекты. Остальные проекты при необходимости очистите локальным деинсталлером.

## Проверки и доверие

Вывод исполнителей считается недоверенным: пути и патчи проверяются перед интеграцией. Git worktree изолируют изменения файлов, но не процессы. Проверки проекта выполняются с правами пользователя; используйте TeamLead с репозиториями, которым доверяете.

Реализованные гарантии и границы проверок описаны в документах об [архитектуре](docs/ARCHITECTURE.md), [модели угроз](docs/THREAT_MODEL.md) и [тестировании](docs/TESTING.md).
